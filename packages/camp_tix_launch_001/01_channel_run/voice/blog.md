# Feature-launch writing guide

Observed 8 September 2026 from four published feature-launch articles. This is an original editorial guide for the current Tix draft. The external reference set supplies channel expression and layout patterns; the frozen Tix baseline supplies every product fact. The article's publisher and product remain Tix.

## Which examples to use

| Reference | Reading label | Best use |
| --- | --- | --- |
| A: practical feature announcement | 6-minute reading label | Primary model for a practical feature announcement |
| B: social-listening feature launch | 6 minutes | User-action headings and precise getting-started steps |
| C: AI image and video feature launch | 8 minutes | Demonstrations and use examples; a longer founder-vision register |
| D: process companion | 7 minutes | A deeper process companion with questions and FAQ |

Reference A starts with availability and access, then explains a recognizable work problem. It moves through changes, component walkthroughs, a compact scenario and audience-specific guidance. Screenshots appear beside the relevant explanation. Its closing gives existing customers a concrete in-product action and new readers a separate entry point.

Reference B addresses the reader and their team directly. Headings describe actions or decisions. Short paragraphs explain what the user sees, followed by lists of useful details. The closing names the navigation path and a small first setup task. Apply that operational specificity to the Tix source.

Reference C uses a named founder's perspective, then demonstrates capabilities through prompts, images and video. It discusses workflow consequences and rollout details. Its reported timings, plan availability, testimonials and first-person experiences belong to that source; they supply no Tix evidence.

Reference D opens on a familiar task, answers reader questions and works through a specific handoff. It qualifies research evidence and explains where a broader tool still fits. Use that explanatory depth when it helps the reader understand Tix. Its FAQ is a format option; a launch article need not inherit the whole section.

## Apply the voice

Write to a person doing the work. Prefer a concrete action, screen, question or consequence over an abstract benefit. Use ordinary verbs and contractions. Keep paragraphs easy to scan, then vary sentence length so the article reads aloud naturally.

Use the product-editor register for this draft. The first person requires evidence about the actual publisher. Gabe's prose constraints remain in force: avoid em dashes, repeated rhetorical reversals and stacked punch lines even where an example uses them. This is an editorial adaptation of the observed sample.

## Recommended article shape

1. Name the product and the supported change or current availability.
2. Establish the reader's task and the friction that matters.
3. Explain the supported workflow through a few useful sections.
4. Place the relevant product view beside its explanation.
5. Add one grounded example and necessary capability boundaries.
6. Close with the actual next action from the Tix brief.

This compact structure combines the Reference A and Reference B patterns. Keep the body as long as the evidence needs; the observed reading labels do not prescribe a word count. A waitlist CTA must not inherit any external free-trial terms.

## Metadata and imagery

All four reference pages show an H1, byline, publication date, reading-time label, category tags, hero image and table of contents. The observed meta descriptions measure 136-147 characters. Three SEO titles differ from their visible H1. All four use `summary_large_image` cards. Prepare those fields separately.

The two inspected launch heroes use dark backgrounds, layered product panels, blue/purple accents and a feature icon. All four reference pages include 1200 x 675 body images; Reference A also uses a taller 1200 x 1024 image. The Reference C article embeds demonstrations. For Tix, author a corresponding composition from its permitted assets and accurate UI. Give each image useful alt text.

## Blogger handoff

Return the full article, metadata fields, image brief/placements and a separate Tix claim map for the consolidated review. Keep the source evidence and any unresolved factual issue outside the reader-facing prose. Do not transfer external UI, company authorship, statistics, pricing or endorsements into Tix.
